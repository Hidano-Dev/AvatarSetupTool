## 1. ピークメモリ測定 (AC 4.2) — 合格

8K (8192×8192) / Both / ImagesOnly を実機撮影 (PNG 16 枚生成、成功結果、所要 65.4 秒)。
撮影直前に `UnloadUnusedAssetsImmediate` + GC でベースラインを取り、撮影中のプロセスメモリを
背景スレッドで 15ms 間隔サンプリング (4284 サンプル) してピークを記録した。

design.md の指定カウンタは Profiler の「Total Used Memory (System Used Memory)」= OS が報告する
常駐メモリだが、同期実行中は Profiler のフレームカウンタが更新されないため、同じ意味を持つ
OS 実測値 (Windows の Working Set、`K32GetProcessMemoryInfo`) で読んだ。

| 指標 | ベースライン | ピーク | 差分 | 判定 |
|------|------------|--------|------|------|
| **Working Set (≒ System Used Memory)** | 6,460,719,104 B (6.02 GiB) | 6,999,937,024 B (6.52 GiB) | **539,217,920 B (514 MiB)** | **< 1GB/枚 合格** (設計目標 0.35〜0.5GB とも整合) |
| Private Bytes (補助) | 7,117,656,064 B | 9,104,769,024 B | 1,987,112,960 B (1.85 GiB) | 参考値 |
| マネージヒープ (補助) | 1,088,577,536 B | 2,230,521,856 B | 1,141,944,320 B | 参考値 |
| Unity ネイティブ確保 (補助) | 370,631,236 B | 416,992,096 B | 46,360,860 B | 参考値 |

補足: Private Bytes (コミットチャージ) の差分が大きいのは、タイル読み戻し (`GetPixels32`、
64 MiB/タイル × 16 タイル/枚 × 16 枚) の使用済み配列が Boehm GC の回収待ちでヒープに蓄積し、
未回収領域のコミットと D3D12 ドライバ予約が計上されるため。実際に触れている常駐メモリ
(Working Set) のピーク差分は 514 MiB であり、現行実装の約 1.5〜2GB/枚から大幅に削減されている。

## 2. タイル継ぎ目検証 (AC 1.4) — 合格

実機 GPU で 8K を製品レイアウト A (辺長上限 4096 → 4×4 分割) と境界位置が互いに素な
レイアウト B (上限 3800 → 5×5 分割) で二重描画し比較した (シーンは等価性テストと同じ
高周波ノイズ板 2 枚、SSAA ×2)。A の境界は B ではタイル内部になるため、継ぎ目起因の段差が
あれば必ず差分に現れる。

| 指標 | 値 | 判定 |
|------|-----|------|
| 全画素の最大チャンネル差 | 1 階調 | ±1 階調以内 合格 |
| 製品レイアウト境界の行・列 (両側 1px) の最大差 | 1 階調 | ±1 階調以内 合格 |
| 完全一致画素率 | 99.94 % | — |

補助データとして実出力 PNG (full 構図) のタイル境界の隣接行・列差分 (平均絶対差) も記録した:
- 行: y=2048 → 0.049 / y=4096 → 6.165 / y=6144 → 0.049 (境界から離れた参照行はいずれも 0.000)
- 列: x=2048 → 0.066 / x=4096 → 0.000 / x=6144 → 0.066 (参照列はいずれも 0.000)

y=4096 の 6.165 は画像中央にある実コンテンツのエッジ (構図中心の被写体輪郭・地面境界) による
もので、その他の境界の微小差はモデル輪郭画素のラスタライズ ±1 階調差に相当する。合否は上記の
レイアウト差し替え比較 (境界跨ぎ最大 1 階調) で判定しており、継ぎ目起因の段差は検出されなかった。

## 3. 低 VRAM 環境での SSAA 非降格 (AC 2.2) — 合格

`graphicsMemorySize` の擬似低値 256 MB でタイル辺長上限を算出し、実機で 8K 描画を完走させた。

| 指標 | 値 | 判定 |
|------|-----|------|
| 擬似 VRAM | 256 MB | — |
| タイル辺長上限 | 4096 px (VramFloorMb=1024 の下限クランプが機能) | — |
| 要求 SSAA 倍率 | 2 | — |
| 適用 SSAA 倍率 | 2 (4×4 分割) | **降格なし 合格** |
| 8K 描画完了 (非単色・全長 8192×8192×3) | 完了 | 合格 |

## 4. 時間見積もり較正の収束 (AC 5.3) — 合格

上記 8K / Both / ImagesOnly 撮影 (実測 65.4 秒) の前後で `TimeCalibrationFactor` と見積もりを記録した。

| 指標 | 更新前 | 更新後 | 判定 |
|------|--------|--------|------|
| 較正係数 | 0.8598 | 0.7972 | — |
| 見積もり時間 | 76.5 秒 | 71.0 秒 | — |
| 見積もり誤差 (対実測 65.4 秒) | 11.1 秒 | **5.6 秒** | **誤差半減、収束方向 合格** |

なお計測テストは小型テストモデル (実アバターより軽量) で撮影するため、計測後に較正係数を
計測前の値へ復元しており、ユーザー環境の較正状態は変化させていない。

## 結論

全 4 項目が合格閾値を満たした。タスク 6.2 完了。
