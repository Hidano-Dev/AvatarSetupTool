# Implementation Plan

- [ ] 1. 純ロジック層を実装する (解像度読み取りと最適値算出)
- [x] 1.1 (P) 最適 maxTextureSize 算出ロジックの実装と境界値テスト
  - 選択肢 (32/64/128/256/512/1024/2048/4096/8192/16384) を唯一の正として保持し、幅・高さの長辺以上で最小の選択肢へ切り上げる純関数を実装する
  - 上限 16384 超は 16384 へ、下限 32 未満は 32 へクランプする。Unity API に依存せず状態を持たない
  - 境界値テスト (31→32 / 32→32 / 33→64 / 2048→2048 / 2049→4096 / 4096→4096 / 16384→16384 / 16385→16384、縦長・横長での長辺選択) を作成する
  - 完了条件: 境界値テストが EditMode で全てグリーンになり、戻り値が常に選択肢のいずれかであることが検証されている
  - _Requirements: 2.1, 2.3, 2.4, 2.5, 5.3_
  - _Boundary: TextureMaxSizeCalculator_

- [x] 1.2 (P) 固定オフセット系フォーマットのヘッダ解像度読み取りの実装
  - 対応拡張子判定 (png/jpg/jpeg/tga/psd/psb/bmp/gif/tif/tiff/exr/hdr、大文字小文字不問) と、失敗時に false のみを返し例外を一切伝播しない読み取り入口を実装する
  - ファイルは読み取り専用・共有アクセスで開き、書き込みを行わない
  - PNG・TGA・PSD/PSB・BMP・GIF の 5 フォーマットについて、マジックバイト等の構造検証と固定オフセットからの幅・高さ読み取りを実装する (ヘッダ先頭数十バイトのみ)
  - 幅・高さが 0 以下または非現実的な値 (1,000,000 超) の場合は破損扱いで false とする
  - 完了条件: 5 フォーマットの既知サイズ画像で幅・高さが取得でき、不存在・破損入力では false が返り例外が出ない
  - _Requirements: 1.1, 1.2, 1.4, 4.3_
  - _Boundary: TextureHeaderReader_

- [x] 1.3 走査系フォーマットのヘッダ解像度読み取りの実装
  - JPEG (SOFn マーカー走査、セグメント長スキップ、走査上限 ~1 MB)・TIFF (IFD の ImageWidth/ImageLength タグ、エントリ数上限)・EXR (dataWindow 属性走査、上限 ~64 KB)・HDR (テキストヘッダの解像度行走査、上限 ~8 KB) の読み取りを追加する
  - ピクセルデータのデコードは行わず、走査上限により破損ファイルでも高速に失敗する
  - 1.2 と同一コンポーネントへの追加のため並行実行不可 (1.2 完了後に着手)
  - 完了条件: 要件の 9 フォーマット全てで既知サイズ画像の幅・高さが取得できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 1.4 ヘッダ読み取りのフォーマット別テスト
  - 正常系: 9 フォーマットの最小正常バイト列 (テストコード内で合成、または Unity のエンコード API 出力) を一時ファイルへ書き、既知の幅・高さが取得できることを検証する
  - 異常系: 不存在パス・0 バイト・マジック不一致・途中切り詰めファイルで false が返り例外が出ないことを検証する
  - 読み取り後にファイルの内容・タイムスタンプが不変であること、巨大ダミー (正常ヘッダ + 大きな本体) でも読み取りが即時完了することを検証する
  - 完了条件: フォーマット別テストが EditMode で全てグリーン
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 4.3, 5.3_

- [ ] 2. 初回インポート時の自動調整を実装する
- [x] 2.1 テクスチャ用ポストプロセッサの実装
  - テクスチャインポート直前イベントで、インポート設定が未生成 (初回インポート) の場合に限り、ヘッダから読み取った実解像度の長辺から算出した最適値を既定インポート設定の maxTextureSize へ適用する
  - 解像度を取得できない場合は何も変更せず Unity の既定動作に委ねる
  - 書き込むのは maxTextureSize のみとし、他のインポート設定・プラットフォーム別オーバーライドには触れない
  - 処理全体を try-catch で包み、例外発生時は警告ログのみ出力してインポート自体は Unity の既定動作で継続させる
  - 既存の FBX インポート機能・asmdef・AssemblyInfo には一切変更を加えない
  - 完了条件: インポート設定未生成のテクスチャをインポートすると maxTextureSize に実解像度基準の最適値が入り、既存アセットの再インポートでは設定が変わらない
  - _Requirements: 2.1, 2.2, 2.6, 2.7, 4.2, 4.4, 5.1, 5.2_

- [x] 2.2 初回インポート自動調整の統合テスト
  - 4096×4096 PNG を .meta なしで配置してインポートし、maxTextureSize が 4096 になる (既定値 2048 に縮小されない) ことを検証する
  - 非 2 のべき乗解像度の画像で長辺以上へ切り上げた最適値が適用されることを検証する
  - インポート済みアセットの maxTextureSize を手動変更後に再インポートしても値が保持されることを検証する
  - 対応拡張子だが内容が破損したファイルのインポートで設定が変更されず、インポート自体は完了することを検証する
  - テストで生成した一時アセットは必ず削除する
  - 完了条件: 上記ケースの統合テストが EditMode で全てグリーン
  - _Requirements: 2.1, 2.2, 2.6, 2.7_

- [ ] 3. 検証・修正サービスを実装する
- [ ] 3.1 (P) テクスチャ列挙と maxTextureSize 検証の実装
  - 選択パス群 (ファイル・フォルダ混在・複数選択) からテクスチャアセットパスを重複なく列挙する。フォルダはサブフォルダ込みで走査し、テクスチャが 1 つもなければ空リストを返す
  - 各アセットについて実解像度から最適値を算出し、既定インポート設定の maxTextureSize と完全一致するかを判定して、不一致 (過大・過小とも) を修正候補として収集する。検証フェーズでは設定を一切変更しない
  - 進捗を 1 アセットごとに通知し、通知先がキャンセルを返した時点で中断して部分結果を返す
  - 解像度取得不能等の個別失敗はスキップとして集計し、[TextureMaxSize] プレフィックス付き警告ログにアセットパスと理由を出力して残りを継続する
  - 完了条件: 列挙・検証結果 (修正候補・検証件数・スキップ件数・キャンセル有無) がプログラムから取得でき、検証のみではアセット設定が変化しない
  - _Requirements: 3.2, 3.6, 3.7, 4.1, 4.2_
  - _Boundary: TextureMaxSizeValidator_
  - _Depends: 1.1, 1.3_

- [ ] 3.2 修正適用と再インポートの実装
  - 修正候補の maxTextureSize を最適値へ書き換えて再インポートし、複数件はアセット編集のバッチ化 (try/finally で終了保証) でまとめて反映する
  - 個別の失敗は失敗件数として集計・警告ログ出力して残りを継続し、進捗通知とキャンセル中断 (部分結果返却) に対応する
  - maxTextureSize 以外のインポート設定は変更しない
  - 完了条件: 修正適用後に対象アセットの maxTextureSize が最適値へ変わり、修正件数・失敗件数・キャンセル有無が結果として返る
  - _Requirements: 3.4, 3.7, 4.1, 4.2_

- [ ] 3.3 検証・修正サービスの統合テスト

  - 不一致アセットが修正候補化され、修正適用後に maxTextureSize が最適値へ変わり、それ以外の設定 (テクスチャタイプ・Read/Write 等) が不変であることを検証する
  - 破損ファイル混在時に残りが処理されて件数集計が正しいこと、進捗通知がキャンセルを返すと部分結果 (キャンセル済みフラグ付き) になることを検証する
  - テスト後は生成した一時アセットを必ず削除する
  - 完了条件: 列挙・検証・修正・スキップ・キャンセルの全経路のテストが EditMode でグリーン
